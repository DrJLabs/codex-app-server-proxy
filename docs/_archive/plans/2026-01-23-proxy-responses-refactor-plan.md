# Responses Endpoint Refactor Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Preserve OpenAI Responses parity for `/v1/responses` while keeping Copilot compatibility and the shared chat pipeline intact.
**Architecture:** `/v1/responses` is a wrapper around chat handlers. Request normalization lives in `src/handlers/responses/shared.js`, non-stream conversion uses `res.locals.responseTransform` in `src/handlers/chat/nonstream.js`, and streaming conversion uses `res.locals.streamAdapter` in `src/handlers/chat/stream.js` backed by `src/handlers/responses/stream-adapter.js`.
**Tech Stack:** Node.js 22, Express, SSE typed events, shared helpers in `src/handlers/responses/shared.js`, tests via Vitest/Playwright.

## Goal
- Accept OpenAI Responses request shapes (`input`, `instructions`, and `messages`) and convert safely into chat messages.
- Emit OpenAI Responses output schema (non-stream) and typed Responses SSE events (stream) with consistent tool-call handling.
- Keep `openai-json` output mode as the default and only switch to `obsidian-xml` when configured.

## Assumptions / constraints
- Keep the layered architecture; do not duplicate chat handler logic.
- Maintain Copilot compatibility via `obsidian-xml` output mode and existing detection toggles.
- Preserve `PROXY_ENABLE_RESPONSES` gate unless explicitly requested to remove it.
- Any externally visible behavior change requires updating transcripts and fixtures.

## Research (current state)
- Entry points:
  - `src/routes/responses.js` routes `/v1/responses`, applies `requireStrictAuth` and `requireWorkerReady`, and allows early intercept via `maybeHandleTitleSummaryIntercept`.
- Request normalization:
  - `src/handlers/responses/stream.js` clones the request, uses `coerceInputToChatMessages` from `src/handlers/responses/shared.js`, sets `stream=true`, deletes `instructions/input/previous_response_id`, resolves output mode with `resolveResponsesOutputMode`, and installs `createResponsesStreamAdapter`.
  - `src/handlers/responses/nonstream.js` follows the same input mapping, validates `n`, sets `res.locals.responseTransform = convertChatResponseToResponses`, and calls `postChatNonStream`.
- Streaming output:
  - `src/handlers/responses/stream-adapter.js` emits typed events (`response.created`, `response.output_text.delta`, `response.output_item.added`, `response.function_call_arguments.*`, `response.output_item.done`, `response.completed`, `done`). This is OpenAI Responses SSE behavior and should not be replaced by raw `data:` chunks without `event:` names.
- Non-stream output:
  - `src/handlers/responses/shared.js` builds `output` items via `mapChoiceToOutput` and maps usage fields to `input_tokens/output_tokens/total_tokens`, including `previous_response_id` echoing.
- Output mode control:
  - `resolveResponsesOutputMode` in `src/handlers/responses/shared.js` allows explicit header override; responses handlers pass `copilotDefault` and `copilotDetection` depending on `PROXY_COPILOT_AUTO_DETECT`.
- Tests that anchor behavior:
  - Unit: `tests/unit/responses.shared.spec.js`, `tests/unit/responses-output-mode.copilot.spec.js`, `tests/unit/responses.route.spec.js`.
  - Integration: `tests/integration/responses.contract.nonstream.int.test.js`, `tests/integration/responses.contract.streaming.int.test.js`.
  - E2E: `tests/e2e/responses-contract.spec.js`.
  - Fixtures/transcripts: `tests/fixtures/obsidian-copilot/responses/*`, regenerated by `scripts/generate-responses-transcripts.mjs`.

## Analysis
### Options
1) Keep `/v1/responses` as a wrapper over chat handlers, refining shared helpers and tests for parity.
2) Build a dedicated `/v1/responses` pipeline separate from chat handlers.

### Decision
- Chosen: Option 1.
- Why: It reduces drift, keeps auth/rate-limit/sanitizer behavior consistent, and reuses existing test harnesses.

### Risks / edge cases
- Responses `input` arrays can include roleful `message` items (developer/system) which are currently flattened to text.
- Output mode may flip to `obsidian-xml` unexpectedly if UA detection is used when auto-detect is disabled.
- SSE tool-call event ordering must stay consistent with existing transcripts and OpenAI typed events.

### Open questions
- None. (Assume existing output-mode gating and route gating remain in place.)

```js
const extractTextFromMessageContent = (content) => {
  if (typeof content === "string") return content;
  if (Array.isArray(content)) return extractTextFromInputItems(content);
  if (content && typeof content === "object") return extractTextFromInputItems([content]);
  return "";
};

const isMessageLikeInputItem = (item) => {
  if (!item || typeof item !== "object") return false;
  const role = typeof item.role === "string" ? item.role.trim() : "";
  if (!role) return false;
  if (!Object.prototype.hasOwnProperty.call(item, "content")) return false;
  if (item.type && item.type !== "message") return false;
  return true;
};

const coerceInputItemsToMessages = (items) => {
  if (!Array.isArray(items)) return [];
  const messages = [];
  let buffer = [];

  const flushBuffer = () => {
    const text = extractTextFromInputItems(buffer);
    if (text) messages.push({ role: "user", content: text });
    buffer = [];
  };

  for (const item of items) {
    if (isMessageLikeInputItem(item)) {
      flushBuffer();
      const role = String(item.role || "").trim().toLowerCase();
      const content = extractTextFromMessageContent(item.content);
      if (role && content) messages.push({ role, content });
      continue;
    }
    buffer.push(item);
  }

  flushBuffer();
  return messages;
};
```
Then in `coerceInputToChatMessages`:
```js
if (Array.isArray(body.input)) {
  const coerced = coerceInputItemsToMessages(body.input);
  messages.push(...coerced);
  return messages;
}
```
